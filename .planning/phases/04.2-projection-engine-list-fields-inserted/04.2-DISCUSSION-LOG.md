## Key Model

| Option | Description | Selected |
|--------|-------------|----------|
| Key inside `[]` from payload field | `orders[c.OrderPlaced.order_id]` — explicit payload path | |
| Key inside `[]` from tag pattern | `orders[tag.starts_with("order:")]` — tag extraction expression | |
| Implicit key from join | `orders[]` — key derived from `join` pattern inside block | ✓ |

**User's choice:** Implicit key from join. The `[]` is empty; the join block defines both the item identity and the key value. Tag extraction in `[]` is an implementation detail not exposed in the DSL.

**Notes:** User initially proposed `orders[c.OrderPlaced.order_number]` but during discussion recognized that the tag IS the identity, not a payload field. The key question ("why is a key actually necessary?") led to the implicit model.

## Removal Semantics

| Option | Description | Selected |
|--------|-------------|----------|
| Payload-based: `removed_by event.field` | Key extracted from event payload field | |
| Tag-based: `removed_by alias.EventType` | Engine infers removal key from the event's tag | ✓ |

**User's choice:** Tag-based removal for Phase 5.1. Payload-based removal deferred to a later phase.

**Notes:** User clarified that `removed_by o.OrderCanceled` and `removed_by c.OrderCancelled.order_id` reference different storage locations (tag vs payload). Phase 5.1 implements tag-based only.

## Mutation Model

| Option | Description | Selected |
|--------|-------------|----------|
| Replace entire item | Last-write-wins per event | |
| Selective field update | Same handler operations as scalar/object fields | ✓ |

**User's choice:** Selective field update — list item sub-fields use the same `HandlerSpec` vocabulary as top-level scalars.

## Phase Scoping

## Join Resolution

| Option | Description | Selected |
|--------|-------------|----------|
| Explicit `on` clause | `join tag.starts_with("order:") as o on c.OrderPlaced.order_number` | |
| Implicit via tag | Engine resolves joined stream from the tag on parent-stream events | ✓ |

**User's choice:** Implicit via tag. When a parent-stream event carries a tag matching the join's pattern, the engine uses that tag as the identity of the joined stream instance.

**Notes:** User confirmed this extends to root-level joins too — not just nested objects.

---

## Multiple Tags with Same Prefix

| Scenario | Option | Selected |
|----------|--------|----------|
| Nested object — multiple matching tags | Runtime error (clear message) | ✓ |
| Nested object — multiple matching tags | Take first (fragile) | |
| List item — multiple matching tags | Apply to all matching items | ✓ |

**User's choice:** Runtime error for nested objects, apply-to-all for list items.
