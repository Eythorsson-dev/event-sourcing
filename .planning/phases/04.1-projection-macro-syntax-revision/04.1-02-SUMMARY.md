## Decisions Made

- The outer `{ }` in `projection! { ... }` are mandatory Rust macro invocation delimiters (Rust requires a brace, paren, or bracket immediately after `!`). The plan's acceptance criteria expected `projection! Foo {` patterns (name inline) which is syntactically invalid Rust. Wave 1 correctly used `projection! { Foo { ... } }` and documented this constraint. This SUMMARY preserves that decision.

## Deviations from Plan

### Plan Acceptance Criteria Discrepancy

**1. [Documentation] Plan acceptance criteria expected unreachable grep patterns**
- **Found during:** Task 1 and Task 2 verification
- **Issue:** The plan expected:
  - `grep -c "projection! {" projection_tests.rs` returns `0`
  - `grep -c "projection! Foo {" projection_tests.rs` returns `1`
  These patterns are mutually impossible: `projection! Foo {` is invalid Rust (no macro delimiter between `!` and `Foo`), so the correct form `projection! { Foo {` will always register as `projection! {` in a grep for the outer pattern.
- **Resolution:** The Wave 1 executor correctly identified this Rust constraint and documented it in 04.1-01-SUMMARY.md. The tests use `projection! { Foo { ... } }` which is valid and correct. The plan's grep patterns were written assuming a macro form that Rust cannot compile.
