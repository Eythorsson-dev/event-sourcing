<!-- New syntax the parser now accepts. Use this as the migration template. -->

Phase 4.1 syntax rules:
1. Outer invocation: `projection! Name { ... }` — no wrapping `{ }`, no inner `projection` keyword
2. Comma after each field (trailing comma allowed, final comma optional)
3. Scalar fields: `field_name: handlers,` or `field_name?: handlers,`
4. Object fields: `field_name: { sub_fields }` (non-nullable) or `field_name?: { sub_fields }` (nullable)
5. Sub-fields within object blocks also comma-separated
6. `cleared_by` only on nullable object fields: `field?: { ... } cleared_by alias.Event,`

Example migration:
```rust
// OLD (Phase 4):
projection! {
    projection CustomerView {
        query tag.starts_with("customer:") as c
        name: c.CustomerRegistered.name
        address? {
            city: c.CustomerRegistered.city
        } cleared_by c.AddressCleared
    }
}

// NEW (Phase 4.1):
projection! CustomerView {
    query tag.starts_with("customer:") as c

    name: c.CustomerRegistered.name,

    address?: {
        city: c.CustomerRegistered.city,
    } cleared_by c.AddressCleared,
}
```

Key changes per invocation:
- Remove outer `{ }` wrapping
- Remove `projection` keyword inside
- Add `,` after each field (including the last if desired)
- Change `field? {` to `field?: {` (add `:` before `{`)
- Change `field {` to `field: {` (non-nullable object, add `:` before `{`)
- Add `,` after each sub-field within object blocks
