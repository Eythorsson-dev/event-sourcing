**Phase Goal:** Revise the `projection!` macro to use cleaner, more consistent syntax — removing the redundant inner `projection` keyword, adding comma field separators, unifying object field declaration with `:` before `{`, and enforcing `cleared_by` as a compile-time error on non-nullable object fields

## Goal Achievement

### Key Context: The Outer-Brace Constraint

The PLAN and ROADMAP success criteria describe the target syntax as `projection! Name { ... }` (name inline, no outer braces). During execution, the implementer correctly identified that Rust requires a delimiter token (`{`, `(`, or `[`) immediately after the `!` in any macro invocation — `projection! Name {` is a syntax error in Rust itself.

The canonical form is therefore `projection! { Name { ... } }`. The outer `{ }` are Rust's macro invocation delimiters; the inner `Name { ... }` is the DSL body. The `ProjectionInput::parse` parser receives only the interior of the outer braces as its `ParseStream`, so the parser correctly starts by reading the `Name` ident — the inner `projection` keyword is genuinely gone from the parse path.

The SUMMARY documents this deviation. All test files use `projection! { Name { ... } }` and compile successfully.
