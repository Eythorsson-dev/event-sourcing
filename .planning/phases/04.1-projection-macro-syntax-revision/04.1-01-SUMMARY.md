# Phase 4.1 Plan 01: Projection Macro Syntax Revision Summary

**`projection!` parser revised to Phase 4.1 DSL: removes inner `projection` keyword, enforces `:` before object `{`, adds comma field separators, and rejects `cleared_by` on non-nullable objects at macro expansion time**

- **Files modified:** 4

## Accomplishments

- Removed `input.parse::<projection>()?` from `ProjectionInput::parse` — macro invocation is now `projection! { Name { ... } }`
- Added comma separator parsing in the outer field loop and the sub-field loop inside object blocks
- Unified field-type detection: always parse `:` after name/`?`, then peek for Brace to distinguish object vs scalar
- Added compile-time `cleared_by` rejection on non-nullable object fields using `Error::new_spanned(&name, ...)`
- Updated `lib.rs` doc comment example to reflect new syntax
- Migrated both integration test files (`projection_tests.rs`, `projection_e2e.rs`) to Phase 4.1 syntax
- All 139 workspace tests pass; clippy and rustfmt clean

## Decisions Made

- The outer `projection! { ... }` braces are Rust's macro invocation delimiters — the `ParseStream` receives only the interior. Removing the inner `projection` keyword means the stream now starts directly with the struct name identifier. This is the correct interpretation of "no wrapping `{ }` block" from the plan: the macro is still invoked as `projection! { ... }` but the old double-nesting (`projection! { projection Name { ... } }`) is gone.
- Test files were updated to Phase 4.1 syntax as part of this plan (Rule 3 auto-fix): the old `field? { ... }` syntax (without `:`) would no longer parse, so the existing tests would fail to compile without migration.
