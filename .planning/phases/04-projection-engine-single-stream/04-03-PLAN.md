    pub async fn validate_schemas(
        &self,
        code_schemas: impl IntoIterator<Item = EventSchemaDef>,
    ) -> Result<(), SchemaConflictError> {
        let persisted = self.schema_store.fetch_all().await
            .map_err(|e| SchemaConflictError::Conflict {
                event_type: "unknown".into(),
                expected: EventSchemaDef { event_type: "".into(), fields: vec![] },
                actual: EventSchemaDef { event_type: "".into(), fields: vec![] },
            })?;
        let persisted_map: std::collections::HashMap<String, EventSchemaDef> =
            persisted.into_iter().map(|s| (s.event_type.clone(), s)).collect();
        for code_schema in code_schemas {
            if let Some(persisted_schema) = persisted_map.get(&code_schema.event_type) {
                if !persisted_schema.is_compatible_with(&code_schema) {
                    return Err(SchemaConflictError::Conflict {
                        event_type: code_schema.event_type,
                        expected: persisted_schema.clone(),
                        actual: code_schema,
                    });
                }
            }
        }
        Ok(())
    }

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| EventSchemaDef from code vs persisted | Code schema compared to DB-persisted schema; discrepancy could indicate unauthorized schema change or version mismatch |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04.03-01 | Tampering | Schema stored at first append | mitigate | record_if_new is append-only — existing schemas are never overwritten. An attacker who appends a tampered event_type for the first time sets the canonical schema; the append_with_schemas call at the same time verifies consistency (second append with different schema → SchemaConflict). Tested by record_if_new_is_append_only. |
| T-04.03-02 | Elevation of Privilege | validate_schemas bypassed | accept | validate_schemas is opt-in (called by the application at startup). NoOpEventSchemaStore is the default — callers who want enforcement must opt in. This is by design (unopinionated library). |
| T-04.03-03 | DoS | Unbounded schemas HashMap | accept | In-memory store is bounded by the number of distinct event types in the application, which is a compile-time constant in practice. Not a realistic DoS vector for a library. |
</threat_model>
