## Decisions Made

- `EventStreamExt` uses `fn single(self) -> impl Future + Send` syntax (not `async fn`) to avoid the `async_fn_in_trait` lint and preserve `Send` bounds on the returned futures
- `query.rs` free functions (`event_matches_query`, `event_matches_criterion`) rather than methods on `Query` — keeps query evaluation logic testable in isolation
- Integration tests use `futures::StreamExt::collect` inline via `use futures::StreamExt` in test blocks to avoid importing futures in production code
- `stream_next` helper using `std::future::poll_fn` + `futures_core::Stream::poll_next` avoids adding `futures` as a non-dev dependency to the core crate

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Fixed async fn in public trait causing Send bound issue**
- **Found during:** Task 1 (EventStreamExt implementation)
- **Issue:** `async fn single(self)` in a public trait generates futures without guaranteed `Send`, causing lint warnings and potential misuse in async runtimes
- **Fix:** Changed to `fn single(self) -> impl Future<Output=...> + Send` with `Self: Sized + Unpin + Send` bounds, matching the pattern used in `LogStore`
- **Files modified:** event-sourcing/src/event_log.rs
- **Verification:** `cargo build -p event-sourcing` passes with no warnings
- **Committed in:** 0167fb7

**2. [Rule 1 - Bug] Fixed missing `next()` method on pinned stream**
- **Found during:** Task 1 (EventStreamExt blanket impl)
- **Issue:** `Pin::new(&mut self).next().await` failed — `.next()` comes from `futures::StreamExt` which is only a dev-dependency
- **Fix:** Implemented `stream_next` helper using `std::future::poll_fn` and `futures_core::Stream::poll_next` — no additional production dependency needed
- **Files modified:** event-sourcing/src/event_log.rs
- **Verification:** `cargo build -p event-sourcing` passes cleanly
- **Committed in:** 0167fb7
