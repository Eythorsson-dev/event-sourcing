## StoredEvent Structure

| Option | Description | Selected |
|--------|-------------|----------|
| Single stream per event | Keep `stream_id` on StoredEvent. DCB achieved via projections joining streams. | |
| Multiple streams per event | Event tagged with multiple stream IDs. Complicates append and sequencing. | |
| Tags (zero or more) | Events carry `HashSet<Tag>`. Streams are virtual — defined by queries at read time. | ✓ |

**User's choice:** Tags — events carry zero or more tags. Streams are a virtual concept.
**Notes:** User stated upfront: "an event may belong to one or many streams. The streams are a virtual concept, not a strict requirement. The StoredEvent may contain none or many tags (aka streamIds)." Research agent confirmed this aligns with the canonical DCB model (Sara Pellegrini / Bastian Waidelich).

## StreamId Semantics

| Option | Description | Selected |
|--------|-------------|----------|
| Opaque string | `Tag(String)`, users decide their own convention. Simpler, unopinionated. | ✓ |
| Structured key-value | `Tag { key: String, value: String }` with `Display` as `key:value`. Enables querying by domain. | |

**User's choice:** Opaque string. Users should do what they want — supports global tags like `"premium"` without forced key:value structure.
**Notes:** Initially considered key-value for wildcard query support. User argued that explicitness belongs in the query interface, not tag structure. This allows global/category tags without awkward workarounds. Aligns with the DCB reference implementation which also uses opaque strings.

## Sequence ID Model

| Option | Description | Selected |
|--------|-------------|----------|
| Keep both global + per-stream | Maintain `StreamSequenceId` alongside `GlobalSequenceId`. | |
| Global only | Remove `StreamSequenceId`. Only `GlobalSequenceId` for ordering/identity. | ✓ |

**User's choice:** Global only — remove `StreamSequenceId`.
**Notes:** DCB research confirmed: per-stream sequencing does not exist in the canonical DCB model. Only global sequence position. `GlobalSequenceId` stays as-is.

## LogStore Trait Impact

| Option | Description | Selected |
|--------|-------------|----------|
| Incremental — add query methods alongside existing | Keep `read_stream` and add `read(Query)`. Gradual migration. | |
| Full revision — replace stream-based API with query-based | Remove `read_stream`, `current_stream_sequence`. Replace with `read(Query)`. | ✓ |

**User's choice:** Full revision — clean break to the DCB model.
**Notes:** Research showed DCB reference has a single `read(Query, ReadOptions)` method. `AppendCondition` redesigned from version-based to query-based. This is a breaking change to every layer but necessary before Phase 4 builds on top.

## Tag Collection Type

| Option | Description | Selected |
|--------|-------------|----------|
| Vec<Tag> | Ordered, allows duplicates. | |
| HashSet<Tag> | Unordered, unique. | ✓ |

**User's choice:** HashSet — explicit user preference.
**Notes:** Tags are inherently unordered and unique per event. HashSet enforces this at the type level.
