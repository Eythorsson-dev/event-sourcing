# Phase 03.2 — Security

> Per-phase security contract: threat register, accepted risks, and audit trail.

---

## Trust Boundaries

| Boundary | Description | Data Crossing |
|----------|-------------|---------------|
| None | Pure in-process Rust library. No network I/O, no filesystem I/O, no user input parsing at runtime. `TagFilter` and `Criterion` are constructed via typed Rust APIs by library callers. | N/A |

---

## Threat Register

| Threat ID | Category | Component | Disposition | Mitigation | Status |
|-----------|----------|-----------|-------------|------------|--------|
| T-03.2-01 | Denial of Service | TagFilter::matches recursion on pathological nested filters | accept | No user-supplied runtime parsing in v1. Arbitrary-depth nesting requires deliberate caller construction; stack overflow only at 10,000+ depth. Revisit if Phase 10 adds runtime query-language parsing. | closed |
| T-03.2-02 | Tampering | serde_json deserialization of attacker-controlled TagFilter JSON | accept | No public deserialization surface in v1. TagFilter is serialized by ProjectionDefinition (Phase 04, builder-constructed) and deserialized only by trusted in-process consumers. No network attack surface. Revisit when Phase 10 adds runtime query-language parsing. | closed |
| T-03.2-03 | Denial of Service | TagFilter evaluation across a large in-memory event log (O(events × filter-depth)) | accept | InMemoryLogStore is a dev/test store only, not a production log. Large-scale performance is a Phase 08 (SQLite) concern. Integration tests bounded to small event counts. | closed |

*Status: open · closed*
*Disposition: mitigate (implementation required) · accept (documented risk) · transfer (third-party)*
