# Plan 03.2-02: TagFilter Integration Tests for InMemoryLogStore

## What was built

Three async integration tests added to `event-sourcing-logstore-inmemory/src/lib.rs` proving that `InMemoryLogStore` correctly evaluates all `TagFilter` variants end-to-end:

1. **`inmemory_evaluates_tag_filter_variants`** — Seeds 4 events with tags `order:o1`, `order:o2`, `premium`, `shipping:ship1` and asserts correct match counts for:
   - `TagFilter::StartsWith("order:")` → 2 events
   - `TagFilter::EndsWith(":o1")` → 1 event
   - `TagFilter::Or([Equals("premium"), StartsWith("shipping:")])` → 2 events
   - `TagFilter::And([StartsWith("order:"), Equals("order:o1")])` → 1 event
   - `tag_filter: None` (match-any) → 4 events

2. **`append_condition_with_starts_with_filter_detects_cross_instance_conflict`** — Proves D-12/D-13: `AppendCondition` with `TagFilter::StartsWith("order:")` correctly returns `ConcurrencyConflict` when a prior `order:*` event exists after the checked position.

3. **`append_condition_with_starts_with_filter_allows_when_no_match`** — Proves the condition correctly permits appends when no matching event exists.

## No store source changes required

`InMemoryLogStore` already delegates tag matching to `event_sourcing::query::event_matches_query`, so Plan 01's `TagFilter` changes flow through automatically.
